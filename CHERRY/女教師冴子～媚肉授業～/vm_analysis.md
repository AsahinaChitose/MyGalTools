# VM 分析定义文档 (vm_analysis.md)

对象: `女教師冴子～媚肉授業～` 脚本 VM（引擎 GsWIN，脚本格式 `GsWIN SC File`，封包内扩展名 SCW）
证据来源: `exe/Saeko.exe` 的 IDA Pro 9.1 反汇编清单 `exe/Saeko_disasm.asm` 与 Hex-Rays 伪代码 `exe/Saeko_pseudo.c`，
以及全部 114 个 SCW 脚本的实测统计。本文件是反汇编/汇编工具的唯一真值源（CLAUDE.md §0）。

---

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 架构 | 单遍解释执行、无操作数栈下推式；命令记录流直接驱动 |
| 指令寻址 | 32 位线性地址，记录 4 字节对齐，每条命令首字段是 32 位 opcode |
| 长度 | 定长（4/8/12/16/20/24/28/32/36/40/44/48/80/84）与变长（`20+12n`、块级 `end`）混合 |
| 文本存储 | 独立文本池（SCW 的 Elem 块），NUL 结尾字符串，按**字节偏移**引用 |
| 文本引用 | ① 值操作数 kind=16；② 消息表记录 `0x00100000`；③ 10 个 opcode 的原生偏移字段 |
| 符号 | 无独立符号表；跳转靠块偏移，资源靠文本池里的名字字符串 |
| 加密/压缩 | 代码块明文；文本块与记录块整体 XOR（`b[i]^=i&0xFF`，SCW 容器层） |
| 校验 | 无 CRC；长度字段为唯一一致性依据 |

## 1. VM 类型与执行模型

`CGameScript` 对象持有：

| 偏移 | 含义 |
|---|---|
| `+112` | **ip**（当前命令指针，指向记录首字节） |
| `+116` | 代码块基址（SCW 头之后的 Size 块） |
| `+124` | 文本池基址（Elem 块，解密后） |
| `+128/132/136` | 代码块基址副本（调用/返回用） |
| `+140` | 记录表（nrec × 20 字节，解密后） |
| `+68` | 运行标志；置 0 表示脚本结束 |
| `+96` | 当前 opcode（出错时打印 `命令コードが不正です :0x%08x`） |

主循环 `sub_40B960`：

```
while (this[68]) {
    v2 = *(u32*)ip;            // 取 opcode
    v3 = ip;
    switch (v2) { ... }        // 二叉比较树，74 个分支
    ip = v3 + len(opcode);     // 各分支自行推进 ip
}
```

证据：`0x40B977 mov eax,[ebp+70h] / mov eax,[eax] / mov [ebp+60h],eax`，
`0x40B98D cmp eax,3A0000h` 起的比较树，以及非法 opcode 时 `loc_40EA0A` 打印 `0x%08x`。

**架构判定**：非栈式、非寄存器式。每条命令只读写一个固定的“脚本工作区”（`this+904..` 起的分层缓冲、120 字节/层的图形层数组、变量数组 `this[36]`/`this[37]`）。
命令之间没有通用寄存器或栈传递，全部通过脚本变量与固定字段通信。

## 2. 指令编码

### 2.1 定长命令

`[u32 opcode][operand dwords...]`，长度固定，例如 `0x000D0000` 为 8 字节、`0x3A0000` 为 24 字节。

### 2.2 变长命令（表达式型）

以 `_STR`（`0x1A0000`）为例（`sub_4123D0` 逐行验证）：

```
+0   u32 opcode (0x1A0000)
+4   value operand (8B)   ; 目标字符串变量
+12  u32 op = 0x1300 (=4864, 赋值)
+16  u32 count
+20  expr_item[count]     ; 每项 12 字节
```

`_IF`（`0x800000`，`sub_412010`）与条件记录同构，只是不带 opcode 字段：

```
+0   value operand (8B)
+8   u32 cmp/arith op
+12  u32 count
+16  expr_item[count]
```

### 2.3 值操作数（8 字节）

```
+0 u16 kind   1 = 整数变量 VAR1
              2 = 整数变量 VAR2
             16 = 字符串：文本池字节偏移
             32 = 字符串：128 字节槽表索引
+2 u16 sub    0x100 = 立即数；1 = 变量间接一次；2 = 间接两次
+4 u32 value
```

`sub_411F40`（取数值）只认 kind=1/2；`sub_4126F0`（取字符串）只认 kind=16/32；
kind=32 走 `sub_412750`：`base + (value << 7)`，即 128 字节/项的独立表（实测索引 ≤ 21，非文本池）。

### 2.4 表达式项（12 字节）

```
+0 u16 kind   (同值操作数)
+2 u16 sub
+4 u32 value
+8 u16 op     0x0100 起始/加, 0x0200 减, 0x0300 乘, 0x0400 除, 0x0500 or,
              0x0600 and, 0x0700 xor, 0x1700 mod, 0x2800 sar, 0x2900 shl
+10 u16 pad   恒为 0xCCCC（编译器填充，必须原样保留）
```

`sub_411D90` 的实现就是对这些 op 做运算符求值（`0x411D90..0x411ECA`）。

### 2.5 块结构 `_LOOP`（`0x1B0000`）

```
+0   u32 0x001B0000
+4   u32 count        重复次数上限
+8   u32 end_offset   块结束偏移（相对本记录起点）
+12  condition        条件记录（16 + 12n 字节）
+..  body             命令序列，直到 起点+end_offset
```

`0x40C948` 起的实现：`ip = v3+12`；`sub_412010` 求条件；条件为假时 `ip = v3 + end_offset`（跳过整块）。

### 2.6 消息表记录 `_MSG`（`0x00100000`）

```
+0  u32 0x00100000
+4  u32 序号
+8  u32 文本偏移   (文本池)
+12 u32 标签偏移   (文本池；0xFFFFFFFF = 无)
```
全样本 8654 条；对话正文全部由这张表引用。

## 3. 文本与符号存储

* **文本池**是独立连续区（SCW Elem 块），NUL 结尾、无对齐、无长度前缀。
  实测 21 211 条字符串。
* **引用方式**（全部为 32 位字节偏移）：
  1. 值操作数 `kind=16 / sub=0x100`：6807 处，全部精确落在字符串起点（0 处落空）。
  2. `_MSG` 记录 `+8`、`+12`：8654 条。
  3. opcode 的原生偏移字段（伪代码里 `*(v3+K) + this[124]`，以及字段普查）：

     | opcode | 字段偏移 | 证据 |
     |---|---|---|
     | `0x070000` | +8,+12,+16,+20 | 字段普查 768/768、738/768 |
     | `0x0A0000` | +8,+12,+16 | 1399/1399 |
     | `0x0D0000` | +4 | 1698/1698 |
     | `0x1D0000` | +4 | 340/340 |
     | `0x230000` | +4,+8 | 选项记录（文本 / 标签） |
     | `0x260000` | +4 | `sub_411D00` |
     | `0x320000` | +8 | 13/14 |
     | `0x330000` | +4 | 237/237 |
     | `0x400000` | +4 | `sub_413490` |
     | `0x4C0000` | +4 | `sub_4134D0/4134B0` |
     | `0x4D0000` | +4 | `sub_4134B0` |
     | `0x4E0000` | +4 | `sub_4134D0(…,1)` |
     | `0x5E0000` | +40 | 4/4 |
     | `0x620000` | +40,+44 | 20/20 |
     | `0x150000` | +4 | `sub_4067E0` |
     | `0x160000` | +4 | `strncpy(this+644)` |
     | `0x170000` | +4 | `dword_43CDB0+5452` |
     | `0x180000` | +4 | `strncpy(this+644)` |
     | `0x120000` | +8 | `sub_4067E0` |

     普查方法：对每个 opcode 记录逐 4 字节字段统计「值落在字符串起点」的比例，
     只收录比例 ≥ 93% 且样本 ≥ 4 的字段。`0x230000` 是用选项数据人工发现的
     （长度早期误判为 4，现已修正为 16）。

* **符号**：没有独立符号表/字符串表。脚本间的“资源名”就是文本池里的字符串（`BG014A`、`TA01A`、`NONE` 等），
  通过上述三种偏移引用；记录表（20 字节/条：`char name[16] + u32`）是标签/调试名，其 u32 不是文本偏移
  （实测仅 1.1% 落在字符串起点）。
* **kind=32 的 128 字节槽表**是另一块内存（`this[0x9C]`），与文本池无关，重定位时不需要动。

## 5. 跳转与块

* 唯一的控制流是 `_LOOP`/`_IF` 的**块偏移**（相对记录起点的 u32），没有绝对地址。
* 因此不存在“跳转目标未对齐”问题；块边界由 `end_offset` 唯一确定。
* 反汇编时可以按块嵌套生成标签 `loc_<offset>`，汇编时按块重新计算偏移。

## 6. 一致性校验（工具必须满足）

1. 解析完整个代码块，不留空隙（`Σlen == Size`）。
2. `0x68 + Size + Elem + nrec*20 == 文件长度`。
3. 所有文本引用（三种方式）落在字符串起点。
4. 空改往返逐字节一致。

已验证：114/114 脚本满足 1–2；空改往返 114/114 逐字节一致；
全部字符串 +3 字符后重汇编 114/114 通过，8654 条消息文本与预期一致。
