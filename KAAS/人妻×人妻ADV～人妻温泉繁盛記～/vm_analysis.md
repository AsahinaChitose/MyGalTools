# KAAS 脚本 VM 分析（wwadv.id）

《人妻×人妻ADV～人妻温泉繁盛記～》（DISCOVERY，2006-06-23）使用的 **KAAS**
引擎脚本格式分析。引擎标识来自 `wwadv.exe` 偏移 `0x47A60` 的字符串：

```
KAAS15 人妻ADV Edition build 35 Copyright(C)1985-2006 karry(TKCOB)
```

即 KAAS 第 15 版、build 35；本文简称 **KAAS**。脚本文件 `wwadv.id`
（1,736,800 字节，SHA-256 `E122A6644E6F735A1D2C26759ACC6EEA4FA9B84079B72536B5741627A7A733D9`）
由该引擎的解释器 `sub_42F590` 执行。

本文档是本工程解析 `wwadv.id` 的唯一真值来源，内容来自对 `wwadv.exe`
（PE32 / MSVC，Hex-Rays 反编译，见 `exe/wwadv.pseudo.c`）的静态逆向，
以及对本样本的结构自校验。任何偏移、opcode 或长度规则一旦与本文不符，
以重新分析的结果为准并更新本文。

---

## 1. 结论摘要

| 项目 | 结论 |
|---|---|
| 引擎 | KAAS（KAAS15 / build 35，karry(TKCOB)） |
| 容器 | 文件头 8 个 u32 + 代码区 + 文本区 + 3 张跳转表 |
| 指令风格 | 定长/变长混合的 dword 操作码 + 内联操作数；栈式调用 + 变量槽 |
| 操作数模型 | “值描述符” 2 个 dword：`type`,`value` |
| 文本存储 | 独立文本区，u16 单元流，按 `0x0000` 分记录；**每 u16 与 0x0001 异或** |
| 文本引用 | 指令内联 u16 偏移（相对文本区起点），无独立字符串池索引 |
| 跳转 | 绝对 dword 下标；CALL 的返回地址写入跳转表 B |
| 指令数 | 24258 条（样本） |
| 文本记录 | 3834 条，每条恰好被 1 条文本指令引用 |
| 加密 | 仅文本区 XOR 0x0001，非压缩 |

逆向依据（wwadv.exe 中）：

- 装载：`sub_43A030` 读取整个文件到 `0xCF0654`，随后按
  `hdr[0]`、`hdr[1]` 对 `[4*hdr[0], 4*hdr[1])` 逐 u16 翻转 bit0。
- 解释器主循环：`sub_42F590`，`switch (dword_CF0654[pc])`，pc 为 dword 下标。
- 文本读取：`pc = 0x8` 起；`dword_CD0940 = 操作数 + 2*hdr[0]` 后按
  `*((unsigned __int16*)base + dword_CD0940 + i)` 取 u16，遇 `0x0000` 结束。

## 2. 容器布局

全部小端。文件总长 = `hdr[4]*4 + len(表C)*4`。

```
偏移                      内容
0x00                        u32 hdr[8]
0x20                       代码区，dword [8, hdr[0])
4*hdr[0] .. 4*hdr[1]       文本区（u16 单元，内容已加密）
4*hdr[1] .. 4*hdr[3]       跳转表 A（hdr[3]-hdr[1] 个 u32）
4*hdr[3] .. 4*hdr[4]       跳转表 B（hdr[4]-hdr[3] 个 u32）
4*hdr[4] .. EOF            跳转表 C
```

本样本：`hdr = [0x13A0A, 0x67501, 8, 0x684CB, 0x69EF0, 0, 0, 0]`

| 段 | 范围 | 大小 |
|---|---|---|
| 代码区 | dword 8..80394 | 321544 字节 / 80386 dword |
| 文本区 | 0x4E828..0x19D404 | 1371100 字节 / 685550 u16 |
| 表 A | 0x19D404..0x1A132C | 4042 项 |
| 表 B | 0x1A132C..0x1A7BC0 | 6693 项 |
| 表 C | 0x1A7BC0..0x1A8060 | 296 项 |

### 2.1 三张跳转表

| 表 | 内容 | 是否可派生 |
|---|---|---|
| A | 所有“文本页”指令（`0x0D`/`0x41`/`0x45`/`0x46`）的偏移，升序 | 可，由代码自动生成 |
| B | 所有 `CALL` 的返回地址 `pc+3`，升序 | 可，由代码自动生成 |
| C | 场景/回想入口偏移，升序；来源未完全确认 | 不可，原样保存为 `.ref` 标签 |

样本验证：表 A 4042 项 = 指令计数 208+3590+156+88；表 B 6693 项 = CALL 条数；
三张表的每个值都精确落在指令起始 dword 上。

表 C 的 296 项全部落在指令边界，所指向的指令为：`SETVARS`（`0x28`）202 项、
`MARK`（`0x0C`）93 项、`SOUND`（`0x13`）1 项。它既不是表 A 的子集，也不等于
任何单一指令的集合，因此推测是“可从回想/存档跳入的场景入口”，但生成规则未确认。

## 3. 文本区加密

```c
for (i = 4*hdr[0]; i < 4*hdr[1]; i += 2)
    *(u16*)&buf[i] ^= 1;     // 翻转每个 u16 的最低位
```

- 这是**按 u16 的 XOR 0x0001**，加密与解密是同一个运算（自逆）。
- 因此文本区在磁盘上是“每个 16 位字的最低位被翻转”的状态；
  反汇编器在解析前解密，汇编器在写出后重新加密。
- 只影响文本区，不影响代码区和三张跳转表。
- 实测：解密后文本区可被 cp932 正确解码出连贯日文。

## 4. 指令编码

一条指令 = 1 个 dword 操作码 + N 个操作数 dword。pc 以 dword 为单位。

### 4.1 值描述符（DESC，占 2 个 dword）

| type | 含义 |
|---|---|
| 0 | 立即数，`value` 即数值 |
| 1 | 变量槽，`value` 为槽位下标（<10000）或标志位（>=10000） |
| >=2 | 间接引用：先取变量槽 `value` 的内容，再以其为下标取值 |

求值函数（`sub_42F490`）：`type==0` 返回 `value`；`type==1` 且 `value<10000`
返回 `var[value]`，否则按标志位读取；其它 `type` 返回 `var[var[value]]`。

### 4.2 跳转语义

- `JMP`：`pc = 操作数`（绝对 dword 下标）。
- `CALL`：压入第二个操作数（返回标签下标）到调用栈，`pc = 第一个操作数`。
- `RET`：弹出返回标签下标 `k`，`pc = 表A[k]`。
- 条件跳转：命中则落到指令之后，否则 `pc = 目标操作数`。

反汇编器把所有代码目标渲染为 `loc_XXXXXX`（偏移按字节显示），
汇编器按标签重新计算，因此文本变长不会破坏跳转。

## 5. 文本区与文本流

### 5.1 记录

文本区由 u16 单元组成，`0x0000` 为记录终止符。3834 条记录首尾相接，
总长（含终止符）恰为 685550 u16，与 `hdr[1]-hdr[0]` 一致。

文本指令的第一个操作数是**相对文本区起点的 u16 偏移**；样本中 3834 条记录
与 3834 次引用一一对应，且引用顺序与记录顺序同为升序。

### 5.2 单元编码

每个非控制 u16 单元 = 两个 cp932 字节，低字节在前：

```
u16 = b0 | (b1 << 8)        b0、b1 为原文 cp932 字节序列
例：0x918D -> 字节 8D 91 -> “国”
    0xB2D0 -> 字节 D0 B2 -> “ﾐｲ”（半角假名成对存放）
```

因此文本区**可以整体按 cp932 字节流理解**，但必须以 u16 单元为单位切分。
反汇编器把每个单元解码为可读字符；无法安全解码（含 0x00、控制字节、
往返不一致）时输出 `{{b0:b1}}` 占位符，保证无损。

### 5.3 控制码与记录结构

| 码 | 名称 | 后随 | 说明 |
|---|---|---|---|
| 0x0000 | END | — | 记录终止（汇编器自动补） |
| 0x0001 | BR | — | 消息记录：页内换行；选择肢记录：选项分隔 |
| 0x0002 | PAGE | 1 个 `0x0003` | 分页 |
| 0x0003 | TAG | 2 个 16 位参数 | 语音 / 说话人标记；参数是二进制元数据 |
| 0x0004 | COLOR | 1 个代码 | 颜色（样本未出现） |
| 0x0005 | SIZE | 1 个代码 | 字号（样本未出现） |
| 0x0006 | WAIT | `0x0001` + `0x0003` | 等待式分页（149 次） |

记录分两类：

1. **消息记录**（被 `0x41`/`0x45` 引用，3746 条）：由若干“页”组成，每页以
   `0x0003` + 2 参数开头，页间用 `0x0002`（或 `0x0006 0x0001`）分隔；
   页内 `0x0001` 为换行。19728 页 = TAG 出现次数。
2. **选择肢记录**（被 `0x17` 引用，88 条）：无 TAG，各选项以 `0x0001` 分隔，
   条数等于 `0x17` 指令的第三个操作数（88 条全部吻合）。

**TAG 的两个参数是二进制元数据，不是正文。** 它们只是恰好落在
cp932 双字节区间里（如 `0xB2D0` 会“看起来像” `ﾐｲ`、`0x7930` 像 `0y`），
按字符解码会产生伪日文，改写后还会破坏语音/说话人信息。统计与相关性
（3746 条带 TAG 的记录）：

- 两个参数都不等于 0..6 的控制码，且每次 `0x0003` 后恰好有 2 个参数；
- 第一参数：页级 4291 种取值；若只看每条记录的首个 TAG，则 1348 种。
  多数在一段内递增（疑似语音编号）；`0x5E00`（页级 8991 次 / 记录级 1324 次）
  与 `0x7930`（页级 3377 次 / 记录级 313 次）是两种固定哨兵值，
  `0x7930` 与第二参数 `0xB2DF` 一一对应（各 3377 次），推断为「一平的语音」；
- 第二参数只有 7 种取值（`0xB2D0`~`0xB2D5`、`0xB2DF`），
  `0xB2DF` 与「一平」高度对应，疑似说话人槽位。

去掉这两个参数后，文本区剩余单元 100% 可被 cp932 正确解码。
反汇编器据此按“页”展开，TAG 参数以行尾数字呈现，不再混进正文。

### 5.4 加密与重定位

文本区在磁盘上是加密态；`4*hdr[1]` 必须能被 4 整除（文本区按 dword 计长）。
修改文本导致长度变化时：

1. 汇编器按记录出现顺序重排文本区，重新计算每条记录的 u16 偏移；
2. 所有文本指令的 `tref` 操作数按标签回填新偏移；
3. 文本区若为 2 mod 4 字节，自动补一个 `0x0000` 单元（反汇编显示为 `.pad 2`）；
4. 文件头 `hdr[0..4]` 按新长度重算，随后重新执行 XOR 加密。

## 6. 汇编文本（asm.txt）语法

```
.encoding cp932
.code_start 8

loc_000008:
        JMP          loc_0000D2

loc_007A86:
        TEXT_SCROLL  t_030DCF, 0x50A

t_030DCF:
        MESSAGE       "あぐらをかいた俺の上に、裸の母さんがまたがってくる。", 0x5E00, 0xB2D0
        MESSAGE       "杏「ふふふ……やっぱり、地獄に堕ちるだろうねぇ、あた\nしら……」", 0x87C9, 0xB2D0
        MESSAGE_WAIT  "いいぞ、ははは。ナイス俺。", 0x5E00, 0xB2D0

t_000024:
        OPTION        "うまいな、俺"
        OPTION        "さむいぞ、俺"

.table_c
        loc_... loc_...
```

- `loc_XXXXXX`：代码偏移（此处为字节偏移的十六进制）。
- `t_XXXXXX`：文本区 u16 偏移的十六进制。
- 指令操作数：立即数 `0x..`；描述符 `type:value`；跳转 `loc_*`；文本 `t_*`。
- 文本记录（`t_` 标签后）三种行：
  - `MESSAGE "正文", 语音号, 说话人槽`：一条显示页；记录内第一条隐含 TAG，
    后续每条隐含 `0x0002` 分页；
  - `MESSAGE_WAIT "正文", 语音号, 说话人槽`：对应 `0x0006 0x0001` 分页；
  - `OPTION "选项"`：选择肢，选项之间隐含 `0x0001`；`TEXT`（`0x17`）指令的
    第三个操作数按 `OPTION` 行数在汇编时自动重算。
- 正文里 `\n` 表示换行码 0x0001，`\\` 与 `\"` 为转义；`{{XX:YY}}` 表示一个
  原始 u16 单元的两个字节（不可显示字符时兜底）。
- `.pad N`：文本区对齐填充字节。
- `.table_c`：跳转表 C，每项为 `loc_*`，汇编器按标签回填。

## 7. 未确认项

1. 样本中未出现的文本类指令（`0x37` `TEXT_GROUP`、`0x3F` `TEXT_CHOICE`）的
   布局依据解释器代码推导，尚未用真实数据验证（`0x17` 在样本中出现 88 次，已验证）。
2. 跳转表 C 的生成规则未确认（不是任何单一指令的子集），当前按原值保存。
3. 控制码 `0x0003`/`0x0004`/`0x0005` 的渲染语义只做了行为级推断。
4. `0x1A`（SKIP_IF）的目标是 `imm+4`，未按绝对标签处理，样本中仅 1 条。
