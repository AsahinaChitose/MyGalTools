# HIMAURI(SH System) 脚本 VM 分析

对象：`exe\FUSHIGI.EXE`（HIMAURI Script Engine Ver2.0）
样本：`unpack\FD_001\*.hst`（208 个脚本，来自 FD_001.HXP）
工具：`opcodelist.py` / `disassembler.py` / `assembler.py`
本文档是反汇编与汇编的唯一真值源；所有结论都有 exe 中的地址佐证。

---

## 0.1 VM 类型与解码流程

* 体系结构：**命令分发 + 后缀表达式栈式求值**。脚本不是通用寄存器机，而是
  「一条命令 + 若干个 RPN 表达式/字符串/跳转目标」的线性指令流。
* 指令编码：**变长、字节对齐、无填充**。命令 = `opcode(1B)` + 操作数。
  操作数按 `opcodelist.OPCODES[op]['schema']` 顺序排列，长度由内容自描述。
* 字节序：文件头长度、跳转目标、表达式立即数一律 **大端**；没有小端字段。
* 解码入口：`sub_403D11`（0x403D11）是主循环：

```c
if (ctx->has_lineno) { lineno = BE16(buf+pc); pc += 2; }   // 本作 flag=0，不出现
op = buf[pc++];
if (op == 0xFF) { pop_frame(); return; }
switch (op) { case 0: ... case 0x64: ... }                 // 101 个 case
```

* 跳转一律是 **绝对偏移**（相对文件起始，含 16 字节头），3 字节大端，
  由 `sub_4015B1` 读取：`pc += 3; return (b[pc-3]<<16)|(b[pc-2]<<8)|b[pc-1]`。
* 条件分支由 `*pc += 3` 跳过目标槽实现，见 `0x01/0x02/0x03` 三个 case。

### 文件结构

```
0x00  char magic[8]   "Himauri\0"                      （sub_401000 校验）
0x08  u8   size[3]    整个文件 BE24 长度，含头          （sub_401000 校验 == 读入长度）
0x0B  u8   flag       0=无标题；非 0 时 0x10 起是 NUL 结尾的标题串，指令流随其后
0x0C  u8   reserved[4] 本作全 0
0x10  指令流 ... 0xFF 结束
```

208 个样本的 `flag` 全为 0，但工具保留 `flag/title` 的重建能力。

## 0.2 表达式子系统（`sub_401985`）

一个表达式 = 记号序列，**0xFF 结束**，按 RPN 求值；求值器维护一个 255 深的
值栈（`v44[255]`）与一个「左值描述符」栈（`v43`，记录变量类型/下标）。

记号编码（首字节高 4 位为类别）：

| 记号 | 额外字节 | 含义 |
|---|---|---|
| `0x00`–`0x07` | 0 | 立即数 0..7 |
| `0x08`–`0x0C` | 0 | 立即数 −1..−5（`v = 7 - n`） |
| `0x0D` | 1 | 立即数 0..127 |
| `0x0E` | 2 | 立即数 BE16 |
| `0x0F` | 4 | 立即数 BE32 |
| `0x1y` | 见下 | 读变量 V1[y] |
| `0x2y` | 见下 | 读变量 V2[y] |
| `0x3y` | 见下 | 读变量 V3[y] |
| `0x40`–`0x47` | 0 | 赋值 / 复合赋值（`= += -= *= /= %= &= \|=`） |
| `0x50`–`0x55` | 0 | 比较 `== != < <= > >=` |
| `0x60`–`0x6C` | 0 | 算术/逻辑 `+ - * / % && \|\|` |
| `0x70`–`0x76` | 0 | `neg not rand atan2 sin cos sqrt` |

变量下标：`y = 0..13` 直接用；`y = 0x0E` 时下一字节为下标；`y = 0x0F` 时下两字节 BE16。

变量类型（`sub_40166B` / `sub_4017B5` 的 type 参数）：

| 类型 | 存储 | 语义 |
|---|---|---|
| `0x10`（V1） | `dword_41B5A4[0..255]` | 全局整型变量 |
| `0x20`（V2） | 脚本上下文 `ctx[5..]` | 每个脚本实例私有 |
| `0x30`（V3） | `dword_41B5A4[256..]` | 系统整型变量（引擎保留，脚本里常见 `V3[200..212]` 作状态位） |

赋值语义：先压入左值（变量读记号），再压入右值，最后是 `0x40`–`0x47`。
`0x60`–`0x6C` 只做运算并把结果留在栈上，不写回变量。

样本里实际出现的运算符只有 `0x40`（赋值）、`0x41`（加）、`0x50`（==）、
`0x52`（<）、`0x54`（>）、`0x6B`（&&），其余按 handler 代码定义。

## 0.3 文本与符号的存储

**没有独立字符串池/符号表**——字符串是操作数的一部分，内嵌在指令流里：

* 首字节 `>= 0x20`：NUL 结尾的 CP932 字节串，紧跟在操作数位置（`sub_401D05`）。
* 首字节 `0x01`–`0x05`：字符串变量引用，下一字节为下标。
* 首字节 `0x06`–`0x0B`：字符串变量引用，下两字节 BE16 为下标。
* 首字节 `>= 0x0C`：字符串变量引用，下标由随后的一个表达式给出（`b0-12` 为类型）。
* 首字节 `0x00`：空串。

因此反汇编器**内联**显示文本，汇编器把改动后的文本直接编码回指令流；
不生成、也不允许生成字符串区。

整型/字符串变量没有名字表，用 `V{1,2,3}[idx]`、`S{type}[idx]` 表达。

---

## 0.4 跳转与标签

* 所有 `target` 都是 3 字节大端绝对偏移（0..0xFFFFFF），指向文件内某个命令起点。
* 反汇编器收集全部目标后统一生成 `loc_XXXX`（十六进制偏移）标签，定义行前空一行。
* 汇编器先完整编码（目标处填 0），记录标签偏移后再回填；
  因此**文本长度变化后**所有目标自动重定位，不依赖原偏移。
* `SWITCH` 的跳转表、`CALLADDR` 的目标同样走标签重定位。

---

## 0.5 对齐与填充

**无对齐、无填充**：208 个样本中命令与操作数逐字节紧邻，末尾直接是 `0xFF`，
不存在记录边界、指针表或对齐空洞（证据：全量往返逐字节一致，且没有任何
未被任何指令消费的字节）。因此工具不输出 `.align`，也不允许凭空插入填充。

---

## 0.6 未定义 opcode 的处理流程

反汇编器遇到 `opcodelist.OPCODES` 里没有、或 `schema is None`（操作数格式未确认）
的 opcode，会**立即报错并给出偏移**，不会猜测长度继续解析：

```
[-] xxx.hst: 操作码 0x15(DIALOG) 的操作数格式尚未确认，位置 0x02AA
```

修正流程：回到 `FUSHIGI.EXE` 的 `sub_403D11` 对应 case，按 `sub_401985/401D05/
40159F/4015B1` 的调用顺序补全 schema，写入 `opcodelist.py`，再全量重跑。

## 0.9 工具用法

```
python disassembler.py <脚本文件或目录> [-o <输出目录或文件>] [--encoding cp932]
python assembler.py   <asm.txt 或目录> [-o <输出文件或目录>] [--encoding gbk]
```

* 反汇编输出 `<名字>.asm.txt`（UTF-8），默认写在输入同目录。
* 汇编输出沿用原文件名（asm 头部 `.source "0000.hst"`），没有该行时默认 `<名字>.hst`；编码优先级 `--encoding` > asm 头部 `.encoding` > `gbk`。
* 目录输入即批量处理；把文件拖到脚本图标上等同于 `disassembler.py <文件>`。
* `--no-verify` 可跳过反汇编器的自动往返校验（批量时更快）。

### asm 语法速查

```asm
.header 0x00, 0x00000000     ; flag, reserved
.encoding cp932

    CALLSCRIPT 53, { 2, "BG_06" }
    EVAL       (V3[201] = 0)
    SWITCH     V1[0], { loc_07C9, loc_086D }
    CALLHXP    "INITIAL.HXP", 18, 1, { }

loc_07C9:
    JFALSE     (V3[200] == 0), loc_086D
    JMP        loc_0909
    END
```

* 表达式：全括号中缀，变量 `V1[201]`，字符串变量 `S18[0]`，函数 `sin(x)`。
* 文本：`{{XX}}` 表示单个不可直接显示的字节；`{{0D}}`/`{{0A}}` 是 CR/LF；
  `\\` 是反斜杠。文本里不出现 `\xNN`。
* 文本被修改后，长度、后续偏移与所有跳转目标由汇编器自动重算。

## 0.10 已知限制

1. 0x0B–0x64 中除样本实际出现的 6 个 opcode 外，操作数 schema 来自 handler 的
   `sub_401985/401D05/40159F/4015B1` 调用顺序推断，**未经样本验证**；
   其中 `0x15/0x17/0x18/0x1C/0x20/0x21/0x3A/0x40/0x45/0x55/0x56/0x5D` 未确认，
   遇到时工具会明确报错而不是产生错误字节。
2. 字符串变量引用（`S...`）在样本中一次都没出现，其三种下标记号形式只按
   `sub_401D05` 的代码实现，未做真实样本回放。
3. 跳转目标按「文件绝对偏移」处理；若将来遇到 `flag!=0`（带标题）的脚本，
   已按同一规则实现，但没有样本可验证。
4. 表达式里 `0x62`–`0x67`、`0x48`–`0x4F`、`0x77`–`0x7F` 等记号未在样本出现，
   解析器按 `sub_401985` 的分支保留但不使用；遇到会报「未知表达式记号」。

* 字符串变量引用三种形式：`S3[40]`（2 字节）、`S3w[40]`（3 字节）、`S3[(表达式)]`。
* 立即数宽度：0..7 内联；8..127 单字节(0x0D)；128..32767 16 位(0x0E)；其余 32 位(0x0F)。
