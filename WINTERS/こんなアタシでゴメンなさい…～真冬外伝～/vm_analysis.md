# vm_analysis.md — IAGS_ISD_01 脚本虚拟机分析

本文件是 `opcodelist.py` / `disassembler.py` / `assembler.py` 的唯一真值来源。
所有结论都给出证据；未证实的部分明确标为「未确认」。

- 宿主：`exe\真冬外伝.exe`（PE32，C++Builder，ImageBase 0x400000）
- 分析工具：IDA Pro 9.1（`idat.exe -A -S` 批处理），导出见 `exe\pseudocode.c`、`exe\asm.txt`
- 样本：`SCR.IFP` 的 31 个脚本块（`SCR_unpacked\SCR#00001`、`SCR#00101`..`SCR#00130`）
- 结论可信度：结构、指令定长、opcode 分派 = 高；单个 opcode 的业务语义 = 中（部分只到「参数摆在哪」）

---

## 1. 容器：ISD 块

`SCR.IFP` 的每个 `type=21` 条目就是一个 ISD 块。块内是「魔数 + 5 段」：

```
+0x00  char[12]  "IAGS_ISD_01 "     魔数（注意末尾 1 个空格，共 12 字节）
+0x0C  5 × { u32 length; byte[length] }
```

| 段 | 名称 | 内容 | 证据 |
|---|---|---|---|
| 1 | code | 指令流，每条 8 字节 | `sub_48B798` 读 12 字节后取第 1 段到 `byte_498610`；`sub_48DC00` 按 8 字节步长取指 |
| 2 | names | 标签名表 | `sub_48D99C` 用 `dword_51862C` 里的名字反查下标，再匹配 `0x4E` 记录 |
| 3 | calls | 跳转目标名表 | `0x40`/`0x41` 用 `dword_518630[op1]` 取名字 |
| 4 | voices | 语音文件名表（`V00001`…） | `sub_48B798` 末尾循环把 `dword_518638` 的字符串灌进 `dword_569814`，`0x60` 用 `op2` 索引 |
| 5 | texts | 正文表 | `0x60` 用 `dword_518634[op1]` 取正文 |

- 5 段长度和必须正好等于块长（31 个样本全部满足，无尾部残留）。
- 第 2–5 段都是「若干条 `\r\n` 结尾的行」；空段长度为 0。
- 31 个样本的分段尺寸全部符合，说明没有夹带压缩或加密（BMP/PNG 载荷另见 `translation-state.md`）。

## 2. 指令编码

定长 8 字节，小端：

```
+0x00  u8   opcode
+0x01  u8   flags
+0x02  i16  op1
+0x04  i16  op2
+0x06  i16  op3
```

证据（`sub_48DC00` 开头）：

```c
dword_518618 = byte_498610[8 * PC];        // opcode
dword_51861C = byte_498610[8 * PC + 1];    // flags
word_518620  = *(i16*)&byte_498610[8*PC+2];
word_518622  = *(i16*)&byte_498610[8*PC+4];
word_518624  = *(i16*)&byte_498610[8*PC+6];
```

31 个块的 code 段长度都能被 8 整除，且逐条按 8 字节解释后 opcode 全部落在已知集合内 —— 定长结论可靠。

### 2.1 flags：三个操作数的间接寻址

```c
byte_518626 = flags & 1;  byte_518629 = flags & 2;    // op1 用 bankV / bankW
byte_518627 = flags & 4;  byte_51862A = flags & 8;    // op2
byte_518628 = flags & 0x10; byte_51862B = flags & 0x20; // op3
if (flags & 1)  op1 = word_51863C[op1];   // bankV
if (flags & 2)  op1 = word_518FAA[op1];   // bankW（在 bankV 之后，故两位同置是 W[V[x]]）
```

- `bankV` = `word_51863C`，`bankW` = `word_518FAA`，都是 16 位变量数组。
- 样本里出现的 flags 只有 `0x00`、`0x02`、`0x04`、`0x05`（外加 `END` 的 `0xFF`）。
- 反汇编记法：`V[x]` / `W[x]`，两位同置写成 `W[V[x]]`；汇编器按包裹层数还原 flags。

## 3. 控制流模型

| 机制 | 说明 |
|---|---|
| `0x7F` | 标签定义点，`op1` = 标签 id，运行时无动作 |
| `0x7E` | 跳转到 id 等于 `op1` 的 `0x7E`/`0x7F` 记录 |
| `0x70`/`0x71`/`0x72`/`0x73` | 条件跳转：`op1` = 标签 id，比较 `op2` 与 `op3`（`!=` / `==` / `>=` / `<=`） |
| `0x4E` | 标签定义，`op1` = names 表下标 |
| `0x40`/`0x41` | 按名字跳转 / 调用，`op1` = calls 表下标，`op2` = 目标脚本号（非 0 时先 `sub_48B798` 切换脚本） |
| `0x4F` | 从调用返回（弹 `word_518A84` 返回栈，并切回原脚本） |

- 跳转目标解析：`sub_48D964` 从 PC+1 往后扫描 `op ∈ {0x7E,0x7F}` 且 `op1 == 目标 id` 的记录，命中即返回其下标；扫到 `0xFF` 返回 -1。
  所以 `0x7E` 记录本身也可以是跳转目标（某些块用它做「跳到下一段」的落脚点）。
- 按名字跳转：`sub_48D99C` 先在该块的 names 段里找名字对应的下标，再找 `op1` 等于该下标的 `0x4E` 记录。

## 4. Opcode 表

`length` 一律 8。`min_args` 是语义上必须写出的操作数个数（尾部为 0 的省略，非 0 时反汇编器会补写）。

| opcode | 助记符 | min_args | 语义 | 证据 |
|---|---|---|---|---|
| 0x10 | IMG | 1 | 显示图片，`op1` = GRP 槽号（0 = 清空） | `case 16: sub_48DB10(pc,0); dword_518A90[0]=op1; if(op1) sub_48B330(op1,0,0)` |
| 0x11 | IMG2 | 3 | 显示到指定层：`op1`=层(0/1)，`op2`=图片 id，`op3`=偏移 | `case 17:` 同上，写 `dword_518A90[op1]` / `dword_518A98[op1]` |
| 0x20 | GFX | 2 | 图形/动画命令，`op1` = 子命令（样本里 1、41..46） | `if (op == 48) sub_488880(op2, op1, op3)` |
| 0x30 | BG | 2 | 画面/背景切换，`op1` = 通道 0..7 | `sub_488880(word_518622, word_518620, word_518624)` |
| 0x31 | BG2 | 2 | 同上变体，样本里 `op1`=1、`op2`=1..5 | `sub_488B10(op2, op1, op3)` |
| 0x40 | JUMP | 2 | 按名字跳转（`op2` 非 0 先切脚本） | `case 'A'(0x41)` 与 `case 64` 共用 `LABEL_64` |

| 0x4F | RET | 0 | 从调用返回 | `case 'O': word_518A3E = dword_518A40[word_518A84]; PC = SHIWORD(...)` |
| 0x50 | SET | 2 | `op1 ← op2` | `case 'P'` |
| 0x51 | ADD | 3 | `op1 ← op2 + op3` | `case 'Q'` |
| 0x52 | SUB | 3 | `op1 ← op2 - op3` | `case 'R'` |
| 0x53 | MUL | 3 | `op1 ← op2 * op3` | `case 'S'` |
| 0x54 | DIV | 3 | `op1 ← op2 / op3`（除 0 得 0） | `case 'T'` |
| 0x55 | MOD | 3 | `op1 ← op2 % op3`（除 0 得 0） | `case 'U'` |

## 5. 文本与名字表的索引规则（重封包的关键）

- 正文表：`\r\n` 分隔的若干行，`MSG` 的 `op1` 就是**行号**。31 个样本逐块核对：
  `MSG`/`MSG_H` 的 `op1` 恰好是 `0 .. N-1` 的排列，N = 正文行数，一一对应。
- 语音表：`MSG` 的 `op2` 就是 voices 段的行号；同一块内 `op2` 互不重复且按升序出现。
  注意：不同行号的语音**文件名可能重复**（`SCR#00001` 里有 6 组重名），所以汇编器按出现顺序编号，不做去重。
- 标签名 / 调用名表：下标就是 `0x4E` / `0x40` / `0x41` 的 `op1`；`0x4E` 的下标按升序出现，
  调用名表的下标按「首次出现顺序」排列，且全部被引用到（34 个名字 / 47 次调用）。

这三条是「反汇编时把表内联到引用点、汇编时按索引重建」能成立的前提；31 个块全部通过零突变验证。

## 6. 未确认 / 保留项

- `0x20` 的子命令 41..46、`0x88` 的子命令 101/111/121/141/777 的具体业务含义未逐一定义，
  反汇编只按数值输出，不影响回封。
- `0x68` 与 `0x60` 的差别只确认到「走不同的上屏路径」，未确认是否对应「有无语音/不同窗口」。
- `flags` 的 `bankV`/`bankW` 具体是「局部/全局变量」还是「变量/常量」，未确认；工具只保证位级还原。
- `0x10`/`0x11` 的 `op1` 是 GRP 槽号这一点有调用链证据（`sub_48B330` 用同一套 TOC），但槽号到具体图像含义的映射未整理。
