# C4 Mp17 脚本格式与工具用法

分析样本为《Don’t Stop ママ！》的 `C4.EXE` 和 `MPX` 目录中的 44 个剧本。助记符按 C4 行为命名。

## 使用

在 `scripts` 目录运行，Python 需要 3.10 或更高版本。

```powershell
python disassembler.py ..\MPX -o ..\mpx_asm --encoding cp932
python assembler.py ..\mpx_asm -o ..\mpx_gbk --encoding gbk

python disassembler.py ..\MPX\STARTUP.MPX -o STARTUP.asm.txt --encoding cp932
python assembler.py STARTUP.asm.txt -o STARTUP.MPX --encoding gbk
```

- 目录输入处理该层全部 `.MPX` 或 `.asm.txt` 文件，汇编也识别名为 `asm.txt` 的文件。命令可接收多个路径，支持 Windows 将文件拖到对应的 `.py` 脚本图标。省略 `-o` 时，按输入名在原目录生成 `名称.asm.txt` 或 `名称.rebuild`。汇编指定输出目录时，每个输出使用 `名称.MPX`。
- `.asm.txt` 始终为 UTF-8。反汇编默认按 CP932 解码。汇编省略 `--encoding` 时沿用 `.encoding`，可用于确认零突变。显式使用 `--encoding gbk` 时，所有正文和选项都会重编码，包括编辑前后相同的字符串。
- GBK 无法表示本作的 `♪`、`・`、`≫`。工具分别写成 `※`、`·`、`＞＞`，并逐文件报告替换数量。其他无法编码的可见字符会带文件、行号和 ID 报错。`{{…}}` 表示明确需要保留的原始控制或不可显示字节。
- 单文件的 `-o` 可指定文件或现有目录。单文件输出到新目录时，可在路径末尾加 `/`。批量输入的 `-o` 按目录处理。

## 编辑 ASM

```asm
loc_0056:
    OFFER_CHOICE loc_0077 @text_003 "はじめからプレイ"
        .when EQ $mode0 200

loc_0061:
    RESET_COUNT_AT 0 1
    SHOW_UPDATE_IF_COUNT 0 0 @text_004 "はじめからゲームをプレイします。%K"
        | "%j,don-op;"
        .update SET $mode0 0 SET $mode1 0
```

- 修改双引号中的内容即可。`|` 拼接上一段文本。行尾是否有换行不改变游戏中的文本。引号用 `\"`，反斜杠用 `\\`，字面 `{` 可用 `\{`。`\n` 对应原始大写 `%N`，小写 `%n` 会保留其大小写。`{{0D}}` 和 `{{0A}}` 分别表示真正的 CR、LF。`{{FF:01}}` 表示两个原始字节。字符串以 NUL 自动终止。
- `.pool` 区规定字符串的物理顺序。`.text_id` 从指令的内联文字取值。`.text` 可定义没有指令引用的条目。共享 ID 的 `.text_id` 带原文 SHA-256，改一处即可同步其余引用。修改为多个不同版本会报冲突。希望某一处单独采用新文案时，须在 `.pool` 明确新增 ID 并修改该处引用。
- 标签是可重定位的。新增或删改指令后，保留目标标签或更新引用。代码地址、字符串偏移、池长度和后续段位置都会重新计算。`OFFER_CHOICE` 的选项文字由专用菜单处理，保留其中的空字符串或文本内容作为选项操作数。
- 文本里的 `%` 指令是引擎控制序列。`%K` 等待继续，`%N` 换行，`%j,don-op;` 在引擎提交当前块时按文件名切换到 `DON-OP.MPX`。跨剧本引用保存为文件名，无二进制地址可链接。更换目标文件名时，目标 MPX 需随游戏放在可加载的位置。引擎逐对显示正文的字节，`_` 是单字节空格控制。选项文字有 67 字节上限。

## 文件布局与重定位

`C4.EXE` 加载器 `0x004047F0` 读入最多 65,536 字节，将代码入口设为文件 `0x10`。头部为 16 字节，所有整数均为小端序。

| 文件偏移 | 类型 | 字段 |
|---|---|---|
| `0x00` | 4 字节 | `Mp17` 签名 |
| `0x04` | `u16` | 字符串池的绝对文件偏移，也是代码结束位置 |
| `0x06` | `u16` | 字符串池字节长度 |
| `0x08` | `u16` | 剧本局部变量计数，样本均为 0 |
| `0x0A` | `u16` | 池后附加区的字节长度，样本均为 0 |
| `0x0C` | `u16` | 尾部符号名数量，样本均为 44。引擎也用此值记录存档中的全局变量数量 |
| `0x0E` | `u16` | 样本均为 0。加载器跳过此字，反汇编保留其值 |

代码顺序解析到字符串池起点。文本使用相对字符串池起点的 `u16` 偏移。池按字节异或 `0x24`，解码后为紧密排列的 NUL 终止记录，空记录也分配自己的 ID。尾部符号名为明文 NUL 终止字符串，支持按顺序将全局变量 `256 + n` 显示为名字。`$lN` 与 `$gN` 分别直接表示变量槽号和全局变量槽号。附加区的实际用途未知，任何内容以 `.byte` 记录保留。段、指令和字符串间没有对齐要求。

选择指令的显式目标是以文件开头为基准的绝对 `u16` 偏移。符合条件时，C4 将条件列表之后的代码地址作为被选中时的隐式续行入口。`CHOOSE` 在运行期根据选项恢复已保存的入口，因此没有立即数跳转操作数。`DEFER_IF` 的失败路径跳过更新列表之后的一个字节，44 个样本此处均为 `COMMIT_BLOCK`。工具验证单字节跳过后仍落在指令边界。

## Opcode 长度和操作数

主分派位于 `0x004054D0`。`target`、`text` 和 `counter` 为 `u16`，`i16` 带符号，`u8` 为单字节。`W`、`U`、`E` 代表下方的条件、更新、表达式列表。指令表已覆盖此分派的有效入口。`02` 和其他未定义主码会报错。

| 字节 | 助记符 | 长度 | 操作数和变体 |
|---|---|---|---|
| `00` | `NOP` | 1 | 前进一字节 |
| `01` | `OFFER_CHOICE` | 5 + W | `target text W`，检查条件并登记选项，然后转到 `target` |
| `03` | `OFFER_CHOICE_ALT` | 5 + W | `target text W`，C4 中与 `01` 的行为相同，原始字节值单独保留 |
| `04` | `SHOW_IF_COUNT` | 6 | `i16 u8 text`，计数相等时显示文本并登记后续计数增加。负索引使用系统槽 1023 |
| `05` | `SHOW_UPDATE_IF_COUNT` | 6 + U | `i16 u8 text U`，显示后执行更新。索引及计数行为同 `04` |
| `06` | `DEFER_IF` | 3 + W + U | `text W U`，成立时登记延迟更新，并显示非空文本，失败时跳过下一字节 |
| `07` | `UPDATE_SHOW_IF` | 3 + W + U | `text W U`，成立时执行更新并显示非空文本 |
| `08` | `OPEN_CHOICE_GROUP` | 1 | 建立一组选项 |
| `09` | `RESET_COUNT_AT` | 4 | `counter u8`，达到阈值时归零 |
| `0A` | `SHOW_IF_COUNT_NO_INCREMENT` | 6 | `counter u8 text`，计数相等时显示 |
| `0B` | `EVAL_STORE` | 1 + E | 执行逆波兰表达式并写入变量 |
| `FE` | `COMMIT_BLOCK` | 1 | 应用延迟更新和计数变更，根据待加载剧本名切换文件或回到本剧本入口 |
| `FF` | `CHOOSE` | 1 | 运行选项菜单，按选择结果设置下一条指令的位置 |

条件列表 `W`（`0x00404E60`）以 `00` 结束，空列表为真。`01 GE`、`02 GT`、`03 LE`、`04 LT`、`05 EQ`、`06 NE` 各带两个 `i16` 操作数。`08 AND`、`09 OR` 各占一个字节，用于把下一比较结果与累计值合并。更新列表 `U`（`0x00404D10`）以 `00` 结束。`01 SET`、`02 ADD`、`03 SUB` 各带两个 `i16` 字，第一个操作数是以 `~slot` 编码的变量槽。以上两组的通用值操作数中，非负 `i16` 为立即数，负数表示 `~value` 槽号。`.when` 或 `.update` 行为空时，汇编器仍会写组终止字节。

表达式列表 `E`（`0x00405210`）由 `u16` 字组成。`FDFA MOD`、`FDFB DIV`、`FDFC MUL`、`FDFD SUB`、`FDFE ADD` 各弹出右操作数并合并。`FDFF STORE` 后跟一个非负 `i16` 变量槽号，并结束表达式。其余字用通用值编码入栈，ASM 写为 `PUSH`。C4 栈容量为 32 个值。

文本控制分派独立于代码（`0x0040B600`）。命令字母的大小写在运行时等价，工具保留文件中的写法。无参数命令有 `i k l n q r y`，基本参数形式为 `%字母,参数;`，包括 `e f j m o s v w` 和 `g`。`g` 还支持 `b c f n` 子码，例如 `%gb,bg01;`。`j` 记录剧本名，`g` 记录图像名，`m` 和 `v` 分别记录音乐和语音名。命令参数与正文一起在内联字符串中编辑。

## 验证

- 使用全部 44 个原始 MPX 执行 CP932 反汇编和重汇编。每个文件逐字节相等，SHA-256 全部一致。
- 使用同一批 ASM 输出 GBK，独立解开 44 个成品的字符串池，966 个字符串记录全部通过严格 GBK 字节比对。原文共有 19 个 GBK 替换实例。核对了原始 `%j` 的 44 个不同目标名均存在。
- 使用 `STARTUP.MPX` 测试加长 GBK 选项并移动代码，确认选项和其余引用随文本池重定位，引用目标随代码标签移动。用构造样本覆盖原始脚本中未出现的有效 C4 opcode，验证所有子码、控制字节和附加数据往返，以及单处共享编辑与冲突报错。
- 验证使用二进制结构和 IDA 中的 C4 代码。原版 EXE 的 GBK 字形、字体和游戏内显示尚未实测。
