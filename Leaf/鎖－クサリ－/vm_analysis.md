# SDT 脚本虚拟机分析（vm_analysis.md）

目标：**鎖－クサリ－**（kusari.exe，2005，PE32）
引擎：**xlvns**，脚本容器版本 `(76, 70)`，即文件头 `4C 00 46 00`（UTF-16LE 的 "LF"）。

本文件是 [`opcodelist.py`](opcodelist.py) 的说明文档，也是[`disassembler.py`](disassembler.py) / [`assembler.py`](assembler.py) 的依据。

---

## 1. 体系结构

| 项目 | 结论 |
|---|---|
| 类型 | 寄存器机 + 调用栈（非纯堆栈机） |
| 寄存器 | 工作寄存器区位于上下文 `+0x0C00`，每个 4 字节；索引为 1 字节，实际使用 `R0..R49` |
| 栈 | 独立栈区 `+0x0400`（调用/返回地址、`PUSHREGS` 保存的寄存器组） |
| PC | 相对字节码起点的**字节偏移**（不是指令下标），存于上下文 `+0x0CC8` |
| 指令编码 | 小端；操作码 `uint16`；无固定对齐 |
| 文本 | **内嵌**在指令操作数中（长度前缀 + Shift-JIS 字节），没有独立字符串区 |
| 符号 | 无符号表；跨脚本调用用文件名（`CHANGE_SCRIPT`），脚本内用绝对 PC 偏移 |

上下文结构（`sub_41D3A0` 分配，大小 `0xE58`）：

```text
+0x0000  uint32[256]  脚本块入口表（SDT 头部 256 个 dword 原样拷入）
+0x0400  uint32[]     调用栈（保存返回 PC）
+0x0C00  uint32[]     工作寄存器（实际使用 R0..R49）
+0x0CC8  uint32       PC
+0x0CCC  uint32       栈指针
+0x0CD8  uint32       等待计数 / 等待截止时间
+0x0CE0  uint8        执行状态（0=停止 1=运行 2=等帧 3=等时间 4=阻塞）
+0x0CDC  void*        解压后的字节码（`dword_AABC74`）
```

## 2. 文件布局

```text
+0x0000  char[4]      "L\0F\0"（uint16 76, 70）
+0x0004  uint32       文件总长度（含 1032 字节头）
+0x0008  uint32[256]  脚本块入口表，元素为 1 基 PC（0 表示块不存在）
+0x0408  ...          字节码，PC=0 对应此处
```

本作 560 个脚本的入口表都只有 `[0] = 1`，即单块脚本。

## 3. 指令解码

1. 读取 `uint16` 操作码；
2. `0x01..0x28` 为引擎内建指令，长度固定（见 `LOW_OPCODES`）；
3. `>= 0x40` 为游戏命令，操作数类型由 kusari.exe 的 `0x4A2770` 表决定：
   每条命令 17 字节，下标 `17*(opcode-64)`，字节 0..14 为类型序列（0 结束），
   字节 15 为“执行后是否阻塞”，字节 16 为变体值个数；
4. 指令之间没有对齐填充，字符串长度字段即边界。

操作数类型：

| 类型 | 写法 | 编码 |
|---|---|---|
| 1 / 7 | `B` | 1 字节立即数 |
| 2 | `C` | 变体值：`00`+uint32 寄存器 / `01`+int32 立即数 / `02`+u8长度+Shift-JIS |
| 3 | `S8` | u8 长度 + 字节串 |
| 4 | `S16` | u16 长度 + 字节串 |
| 5 | `R8` | 1 字节寄存器号 |
| 6 | `CMP` | 寄存器号 + 条件码 + 变体值 |
| 8 / 9 | `H` | u16 立即数 |

## 4. 跳转与标签

| 指令 | 语义 | 目标字段 |
|---|---|---|
| `JCC_RR` / `JCC_RI` | 条件成立则跳转 | 指令内 uint32 绝对 PC |
| `JNCC_RR` / `JNCC_RI` | 条件不成立则跳转 | 同上 |
| `LOOP` | 寄存器减 1，非 0 则跳转 | 同上 |
| `JMP` | 无条件跳转 | 同上 |

目标值是相对字节码起点的偏移，反汇编器统一输出 `loc_XXXXXXXX` 标签，
汇编器两遍扫描后回填；字符串变长导致偏移变化时会自动重定位。
560 个样本中的 505 个跳转目标全部落在真实指令边界上。

## 6. 文本与编码

- 文本只存在于 `S8/S16/C(02)` 操作数中，原文为 **Shift-JIS 字节流**（CP932 是其超集）；
- 反汇编/汇编默认 `--encoding cp932`（也可显式用 `--encoding shift_jis`；两种编码对本作全部样本都能逐字节还原）；
- 控制字节与不可解码字节写成 `{{XX}}`，`"` 与 `\` 分别写作 `\"`、`\\`；
- 同一段文本只出现一次，不存在共享字符串表，因此不存在“多处引用同一 ID”的问题；
- 修改文本后，长度前缀、后续指令偏移、跳转目标全部由汇编器重算。

## 7. 未定义操作码的处理

反汇编时若遇到 `opcodelist.py` 未收录的操作码，立即报错并给出偏移，
不会猜测长度继续解析（见 `disassembler.py` 的 `DisasmError`）。
扩充流程：

1. 在 kusari.exe 中定位该操作码的处理分支（`sub_406ED0` 的 switch 或 `sub_41E090`）；
2. 核对其在 `0x4A2770` 表中的 17 字节 schema；
3. 更新 `opcodelist.py` 的 `HIGH_OPCODES`，重新跑全量反汇编。

python disassembler.py scripts\SCRIPT_unpacked\TEST.SDT -o TEST.SDT.asm.txt
